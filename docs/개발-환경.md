# 개발 환경

**주 개발 기기(Windows + Git Bash)에서만 참인 사실**을 모은다. 규칙이 아니다 — 다른 기기에서는 틀릴 수 있다.
저장소 전체에 걸리는 규칙은 [`CLAUDE.md`](../CLAUDE.md)에 있다. 여기 적힌 확인 날짜보다 오래되었으면 다시 확인한다.

## 셸

- **heredoc을 쓰지 않는다.** Git Bash에서 heredoc은 따옴표를 쳐도 백슬래시와 백틱을 먹어, 정규식이 조용히 망가진 채
  파일에 쓰인다. `.claude/hooks/no-heredoc.mjs`가 막는다(PowerShell 여기-문자열 포함, 따옴표 속 `<<` 글자는 통과).
  스크립트는 파일로 쓴 뒤 실행한다.
- **스크립트에 역슬래시를 넘기면 도구를 거치며 줄어들 수 있다.** 8진수로 읽혀 엉뚱한 글자가 된 적이 있다(2026-08-24).
  `chr(92)`처럼 조립한다.
- **Git Bash의 `grep`으로 한글을 찾지 않는다.** 문자 클래스가 바이트로 쪼개져 거짓으로 걸린다. ripgrep을 쓴다.
- **`npm run ci`가 시작하자마자 node 세그폴트(종료 코드 139)로 죽는 일이 가끔 있다**(2026-09-26 확인). 검사 실패가
  아니니 다시 돌린다.

## gcc

gcc는 PATH에 없지만 CLion이 번들한 MinGW로 설치되어 있다(2026-08-12 확인, GCC 13.1.0).

```bash
export PATH="/c/Program Files/JetBrains/CLion 2025.3.3/bin/mingw/bin:$PATH"
npm run check -- code      # 이러면 .c도 검사한다 (평소에는 gcc가 없다며 건너뛴다)
```

- **폴더째 PATH에 넣는다.** `gcc.exe`만 절대 경로로 부르면 `cc1.exe`·`as.exe`를 못 찾아 **stderr 한 줄 없이
  종료 코드 1로** 끝난다. 컴파일 오류처럼 보이지 않는다.
- 레지스트리 PATH(HKCU\Environment)에만 있어 `command -v gcc`로는 안 보인다. 없다고 단정하지 않는다.

## 커밋 서명(GnuPG)

GnuPG가 두 벌 설치되어 있고 홈 디렉터리가 다르다(2026-08-20 확인).

| | 실행 파일 | homedir | 비밀 키 |
|---|---|---|---|
| Git Bash의 `gpg` | `/usr/bin/gpg` | `C:\Users\user\.gnupg` | 없음 |
| **git이 부르는 gpg** | `C:\Program Files\GnuPG\bin\gpg.exe` | `C:\Users\user\AppData\Roaming\gnupg` | 있음 |

- Git Bash에서 그냥 `gpg`를 치면 **키가 없는 다른 홈**이 잡힌다. 키 · 신뢰 설정은 전체 경로로 부르거나 PowerShell에서 한다.
- `gpg: signing failed: Timeout` — 패스프레이즈 캐시 만료다. 잠시 뒤 다시 시도한다. `--no-gpg-sign`으로 우회하지 않는다.
- `gpg: no default secret key` — 대개 홈이 다른 gpg를 부른 것이다.
- 신뢰 설정 변경은 보안 설정이라 저장소 소유자가 직접 한다.
